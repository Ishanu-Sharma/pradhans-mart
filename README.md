# Pradhan’s Mart (P Mart)

Grocery delivery from Indian brands, for Guwahati only. One Node.js app, no third-party packages.

## Interfaces

| URL | Who | What |
|---|---|---|
| `/` | Customers | Offer, pincode or location check, benefits, FAQ |
| `/shop` | Customers | Catalogue with live stock, search, categories, cart |
| `/checkout` | Customers | Three steps: address, review and pay, confirmation |
| `/order` | Customers | Live order status, rider distance, cancel |
| `/data-request` | Customers | Download or delete personal data |
| `/unsubscribe` | Customers | One-click unsubscribe from offer emails |
| `/privacy` `/terms` `/refunds` `/cookies` `/contact` | Everyone | Policies and business details |
| `/admin` | Store staff | Live orders, status, riders, products, stock, data requests |
| `/rider` | Riders | Assigned deliveries, live location sharing, mark delivered |

Real-time data uses server-sent events: stock in the shop, order status and rider location on the tracking page, new orders on the dashboard, new assignments on the rider app.

## Run locally

Requires Node.js 22 or newer.

```
npm start            # http://localhost:3000, prints a one-off admin password
npm test             # API tests
node tests/e2e.mjs   # browser tests in headless Chrome
npm run icons        # rebuild favicon and app icons from the logo geometry
npm run launch-check # lists everything still blocking launch
```

Environment variables: `PORT`, `ADMIN_PASSWORD` (12+ characters), `PUBLIC_URL` (your https custom domain), `NODE_ENV=production`, `TRUST_PROXY=1` when behind a proxy or load balancer.

Data is stored in `data/db.json`. Back this file up. The host must give the app a persistent disk.

## Launch rules

`NODE_ENV=production` refuses to start until `npm run launch-check` passes. It checks:

1. Every business detail in `config/business.json` is filled in.
2. Every fact in `config/store.json` under `launch` is confirmed (`true`): catalogue prices and MRPs, fees, service area, hours, refund terms, lawyer review of the policies.
3. `PUBLIC_URL` is an https custom domain, not localhost, an IP address, or a hosting platform's default domain.
4. `ADMIN_PASSWORD` is set.
5. The favicon files and all policy pages exist.
6. No "made with", "built with", "generated by" or "powered by" tag, and no em or en dash, anywhere in what visitors receive.

## What you must check before launch

- `server/seed.js`: the starter catalogue. Prices equal recent MRPs and must be checked against your invoices and packs. Add each pack's manufacturer or packer details in the dashboard.
- `config/store.json`: delivery fee (Rs 25), free delivery from Rs 299, hours (7 am to 11 pm), pincodes 781001 to 781040, the store location and the 12 km radius used by the location check, the 48-hour report window and 7-day refund time.
- The policies are drafted against the DPDP Act 2023, the Consumer Protection (E-Commerce) Rules 2020, GST record rules and the Legal Metrology rules. Have a lawyer review them.
- Emails: offer emails are composed with an unsubscribe link and one-click headers, and kept in the outbox inside `data/db.json`. Connect a mail provider before you send any. If you add one, list it in the privacy policy.

## Demo deployment (Render, free plan)

`render.yaml` deploys a presentation build with `DEMO_MODE=1`:

- a banner on every page says it is a demo: orders are not delivered and nothing is charged;
- business details read "Not applicable: demo project" instead of invented numbers;
- orders are open 24 hours so the full flow can be shown at any time;
- every page is hidden from search engines.

Render generates `ADMIN_PASSWORD`; find it under the service's Environment tab. The free plan has no permanent disk, so orders, riders and stock edits reset when the service restarts or sleeps (after 15 idle minutes). Open the site a minute before presenting to wake it.
