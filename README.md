# Pradhan’s Mart (P Mart)

Grocery delivery from Indian brands, for Guwahati only. One Node.js app, no third-party packages.

## Interfaces

Everything except the policy pages needs a sign-in. The site opens on `/login`.

| URL | Who | What |
|---|---|---|
| `/login` | Everyone | Split-screen sign in and sign up, with Customer, Delivery partner and Store partner tabs |
| `/shop`, `/checkout`, `/order`, `/account` | Customers | Catalogue with real photos and live stock, three-step checkout, live tracking, saved address, delete account |
| `/store` | Store partners | Accept or decline order requests (60 s each), pack orders, set stock, go online or offline |
| `/rider` | Delivery partners | Go online, accept or decline delivery requests (45 s each), pick up, deliver, share location while out |
| `/admin` | Admin (password) | Live overview, approve or reject partners, suspend accounts, all orders with cancel, catalogue, data requests |
| `/privacy` `/terms` `/refunds` `/cookies` `/contact` `/credits` `/data-request` `/unsubscribe` | Anyone | Policies, credits and data rights, open without signing in |

### How orders are dispatched

1. A customer places an order. It is offered to one open store at a time: a store in the customer's pincode first, then the store with the fewest orders in hand, and only stores that have every item in stock.
2. The store has 60 seconds to accept. Declining or not answering passes it to the next store; once every store has had a turn, the round starts again. With no open store for 10 minutes, the order is cancelled and the customer is told.
3. Accepting takes the items out of that store's stock. The store packs and marks the order packed.
4. The order is then offered to the online delivery partner who has been free the longest, with 45 seconds to accept, the same way.
5. The partner sees only the store and the drop street and pincode until they accept. After pickup, their location is shared live with that customer and is never saved.

Riders and store partners sign up from the login page and start work after the admin approves them. An approved store starts with the catalogue's opening stock, which it can change.

## Run locally

Requires Node.js 22 or newer.

```
npm start            # http://localhost:3000, prints a one-off admin password
npm test             # API tests
node tests/e2e.mjs   # browser tests in headless Chrome
npm run icons        # rebuild favicon and app icons from the logo geometry
npm run launch-check # lists everything still blocking launch
```

Environment variables: `PORT`, `ADMIN_PASSWORD` (12+ characters), `PUBLIC_URL` (your https custom domain), `NODE_ENV=production`, `TRUST_PROXY=1` when behind a proxy or load balancer.

## Database

Set `MONGODB_URI` to store data in MongoDB (for example a free MongoDB Atlas M0 cluster). Without it the app uses `data/db.json`, which is fine locally but is wiped on hosts without a persistent disk, such as Render's free plan. Optional: `MONGODB_DB` picks the database name (default: the one in the connection string, else `test`).

The app loads everything into memory at start and writes each change back, so run one instance per database. The catalogue is seeded automatically into an empty database. `npm test` also checks persistence against a local MongoDB if one is running.

## Passwords and payments

- Forgot password: a 6-digit code valid for 10 minutes, 5 tries, then the account's other sessions are signed out. With `DEMO_MODE=1` the code is shown on screen. Outside demo mode the option explains that SMS is not set up, until you connect an SMS provider.
- Admin password: the `ADMIN_PASSWORD` setting of the host. Change it there to reset it.
- UPI on delivery is shown but marked not available in demo mode; customers pay cash. A real launch needs a merchant UPI ID or a payment gateway.

## Launch rules

`NODE_ENV=production` refuses to start until `npm run launch-check` passes. It checks:

1. Every business detail in `config/business.json` is filled in.
2. Every fact in `config/store.json` under `launch` is confirmed (`true`): catalogue prices and MRPs, fees, service area, hours, refund terms, lawyer review of the policies.
3. `PUBLIC_URL` is an https custom domain, not localhost, an IP address, or a hosting platform's default domain.
4. `ADMIN_PASSWORD` is set.
5. The favicon files and all policy pages exist.
6. No "made with", "built with", "generated by" or "powered by" tag, and no em or en dash, anywhere in what visitors receive.

## What you must check before launch

- `server/seed.js`: the starter catalogue. Prices equal recent MRPs and must be checked against your invoices and packs. Add each pack's manufacturer or packer details in the dashboard.
- `config/store.json`: delivery fee (Rs 25), free delivery from Rs 299, hours (7 am to 11 pm), pincodes 781001 to 781040, the store location and the 12 km radius used by the location check, the 48-hour report window and 7-day refund time.
- The policies are drafted against the DPDP Act 2023, the Consumer Protection (E-Commerce) Rules 2020, GST record rules and the Legal Metrology rules. Have a lawyer review them.
- Emails: offer emails are composed with an unsubscribe link and one-click headers, and kept in the outbox inside `data/db.json`. Connect a mail provider before you send any. If you add one, list it in the privacy policy.

## Demo deployment (Render, free plan)

`render.yaml` deploys a presentation build with `DEMO_MODE=1`:

- a banner on every page says it is a demo: orders are not delivered and nothing is charged;
- business details read "Not applicable: demo project" instead of invented numbers;
- orders are open 24 hours so the full flow can be shown at any time;
- every page is hidden from search engines.

Render generates `ADMIN_PASSWORD`; find it under the service's Environment tab. The free plan has no permanent disk, so orders, riders and stock edits reset when the service restarts or sleeps (after 15 idle minutes). Open the site a minute before presenting to wake it.
